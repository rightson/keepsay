# 0018 人工批准事項（2026-10-25）

## Context

M2 / M3 / M4a 平行開發暫停時，累積了四項需要人工決定的事項（ROADMAP D-7、D-9、D-12，以及 M3 的 Win32 FFI 與測試規則）。使用者於 2026-10-25 一併批准。

## Decision

1. **D-12：uniffi `cli` feature 與 crate-type。** 允許在 workspace 內新增只做 binding 產生的 bin crate（例如 `uniffi-bindgen/`），只有它開 `uniffi` 的 `cli` feature；keepsay-core 本身仍不開 `cli`。keepsay-core 可加 `staticlib`（與必要時的 `cdylib`）crate-type 以打包 XCFramework。新增的 build 期依賴依 0011 的規則在 M2 的變更紀錄逐項列出 cargo-vet exemption。
2. **M3 Win32 FFI。** `unsafe_code` 的例外擴大到 `windows/src-tauri/src/win32/` 目錄（原生 key 對話框、SendInput、剪貼簿），每個 `unsafe` 區塊需 `// SAFETY:` 註解；CI unsafe-scope 只多放行這個目錄。`windows` crate 在 Windows app 可加開 `Win32_UI_WindowsAndMessaging`、`Win32_UI_Controls`、`Win32_Graphics_Gdi`、`Win32_System_LibraryLoader`、`Win32_UI_Input_KeyboardAndMouse`、`Win32_System_DataExchange`、`Win32_System_Memory`（以及實作 V5 所需的最小補充，於 M3 變更紀錄列出）。
3. **假 key matcher。** 測試可以在 mock server 的 matcher 中比對固定的測試假 key（canary key），以證明 key 只送往正確的 host；不得印出、不得放進斷言失敗訊息。真實 key 永遠不得出現在測試中。
4. **D-7、D-9。** 接受 0007 的翻譯守門門檻校正結果與 light / formal prompt 內容，M2 起以真實模型輸出再校正。

D-11（`uniffi/tokio` async FFI）不在本次批准範圍，仍待決定。

## Consequences

- CLAUDE.md 的 unsafe 與測試規則同步更新。
- M2 可產生 Swift binding 並打包 core；M3 可實作原生對話框、SendInput 與剪貼簿；M4a 可接上真正的 core。

## Status

Accepted（2026-10-25，使用者批准）。
